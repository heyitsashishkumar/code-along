Every real error we hit while running `npm install` and `npm test` in **LWC from Zero #24**, copied word-for-word from our terminal (`bugs.md` `B02`, `B05`, `B06`), never from memory.

## `npm error Cannot read properties of null (reading 'edgesOut')` (`B02`)

Running plain `npm install` in a fresh Salesforce DX project on Node 20 (npm 10.8.2) crashes with:

```
npm error Cannot read properties of null (reading 'edgesOut')
npm error A complete log of this run can be found in: /Users/<you>/.npm/_logs/<time>-debug-0.log
```

- **Why:** a peer-dependency resolver bug in npm 10.8.2 (bundled with Node 20).
- **Fix:** run `npm install --legacy-peer-deps` (or use Node 22+ / npm 11, where `npm install` succeeds without flags).

## `Cannot find module 'lightning/modal' from 'force-app/main/default/lwc/noteModal/noteModal.js'` (`B05`)

When you run `npm test` across the whole project, `noteModal.test.js` and `customerSummary.test.js` fail with:

```
  ● Test suite failed to run

    Cannot find module 'lightning/modal' from 'force-app/main/default/lwc/noteModal/noteModal.js'
```

- **Why:** `@salesforce/sfdx-lwc-jest` 7 ships built-in stubs for most `lightning/*` modules, but does not include a stub for `lightning/modal`.
- **Fix:** mock `lightning/modal` at the top of `noteModal.test.js`:

  ```js
  jest.mock(
      'lightning/modal',
      () => {
          const { LightningElement } = require('lwc');
          return {
              __esModule: true,
              default: class extends LightningElement {
                  close(result) {
                      this.closedWith = result;
                  }
              }
          };
      },
      { virtual: true }
  );
  ```

  And in `customerSummary.test.js`, mock `c/noteModal`:

  ```js
  jest.mock('c/noteModal', () => ({ __esModule: true, default: { open: jest.fn() } }));
  ```

## `TypeError: "createElement" function expects an "is" option with a valid component constructor.` (`B06`)

When `npm test` runs the CLI's generated skeleton test in `ldsUtils/__tests__/ldsUtils.test.js`, it fails with:

```
  ● c-lds-utils › TODO: test case generated by CLI command, please fill in test logic

    TypeError: "createElement" function expects an "is" option with a valid component constructor.
```

- **Why:** `ldsUtils` is a service module that only exports `export function reduceErrors(errors)` (no `export default class extends LightningElement`), so the CLI skeleton's `createElement('c-lds-utils', { is: LdsUtils })` receives `undefined`.
- **Fix:** test `reduceErrors` directly as a plain JavaScript function (`import { reduceErrors } from 'c/ldsUtils';`).
